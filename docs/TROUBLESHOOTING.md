# PropertyCare Diagnostics & Troubleshooting Matrix

This guide provides pre-mapped debugging procedures and root-cause analyses for common engineering issues encountered across the PropertyCare ecosystem runtime.

---

## 1. Node Server Throws `HTTP 401 Unauthenticated` on Inbound Callouts

### Symptom
The external Node.js tenant portal console prints a connection rejection stack trace when invoking custom Apex REST endpoints (`/services/apexrest/api/v1/service-requests/`).

### Root Cause Analysis
1. **Clock Drift (Replay Attack Shield)**: The system time clock on your local hosting machine or server container has drifted out of sync with international UTC standards by more than 3 minutes. Salesforce automatically drops assertion tokens whose timestamps fall outside this grace period.
2. **Expired Certificate**: The self-signed or CA-signed X.509 certificate uploaded to your Salesforce Connected App has expired.
3. **Mismatched Client ID**: The `SF_CLIENT_ID` environmental variable inside the portal's `.env` file does not match the Consumer Key generated by the Connected App configuration layer.

### Resolution Steps
1. Synchronize your local machine's operating system clock with an atomic time server (e.g., run `w32tm /resync` on Windows PowerShell or `sudo ntpdate pool.ntp.org` on Linux).
2. Run `sf org display --target-org DevHub` to confirm that the `clientId` matches your portal `.env` properties perfectly.
3. Check the Connected App setup page in Salesforce to confirm that your user profile/permission set is explicitly pre-authorized under **Permitted Users: Admin approved users are pre-authorized**.

## 2. Change Data Capture (CDC) Status Synchronizations Not Firing

### Symptom
An automated status modification is committed on a `Work_Order__c` record, but the outbound synchronization queueable engine (`VendorSyncQueueable`) is never enqueued.

### Root Cause Analysis
1. **CDC Channel Deactivated**: Change Data Capture has not been declared for the Work Order sObject in the target environment's global setup.
2. **Bypass Flag Active**: The custom metadata or hierarchical execution bypass flags (built in Phase 5) are active for the context user running the transaction, suppressing trigger distribution loops.
3. **Event Bus Ingestion Error**: The database transaction was rolled back late in the processing lifecycle, forcing the platform to suppress the associated event bus publication.

### Resolution Steps
1. Navigate to **Setup** $\rightarrow$ **Quick Find: Change Data Capture**. Verify that **Work Order (`Work_Order__c`)** sits securely inside the *Selected Entities* column box.
2. Run this query in your Developer Console to inspect if any transaction logs caught downstream processing blocks:
   ```sql
   SELECT Id, Operation__c, Status_Code__c, Logged_At__c, Message__c 
   FROM Integration_Log__c 
   WHERE Operation__c = 'VendorSync' 
   ORDER BY Logged_At__c DESC 
   LIMIT 10
